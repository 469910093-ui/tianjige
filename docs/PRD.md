# 天机阁 PRD

## AI 速读卡

- 产品一句话：七流派拟合的移动端 AI 算命社交破冰工具，让饭局朋友用「算命 + 吃什么 + 小游戏」快速破冰，而无需听懂晦涩命理黑话。
- 核心循环：采集生辰地信息 → 七流派算法拟合 → 白话报告 → 今日吃什么/破冰游戏 → 分享复盘。
- 目标平台：移动优先 Web（Next.js 既有仓），桌面可读；P0 不要求原生 App / PWA。
- 硬约束：算法与 AI 分层；娱乐免责声明；不替代医疗/法律/财务建议；不伪造地图 POI；报告必须白话可读。
- 推荐默认：沿用现有七引擎 + `/api/report`；风格蒸馏用「风格包 Prompt」而非抄袭博主原文；周边店铺先用城市+人工/API 降级清单。
- 发挥空间：翻牌动效、报告排版、破冰卡片文案、空状态插画、分享图视觉。
- P0 验收：一次综合测算可出白话四 Tab 报告；可填出生地/常住地；报告后可出「吃什么」与按人数推荐破冰游戏。
- 最容易翻车：报告仍像黑话；地图 API 未就绪却承诺真实周边；酒桌游戏无年龄提示。
- 超预期机会：AI「背锅」话术；七流派冲突可视化；一键生成饭局开场白。

## 第一章：产品概述

天机阁 是一款 移动优先的 AI 命理破冰产品，让 饭局/聚会中的年轻人与命理兴趣用户 能够 用七流派拟合结果拿到白话解读，并顺势得到「今天吃什么」与桌面小游戏推荐，而无需 自己啃晦涩排盘术语或冷场找话题。

### 1.1 差异化对比表

| 功能 | 竞品（通用 AI 算命 / 单流派 App，此处未逐一验证） | 本产品 | 实现方式 |
|---|---|---|---|
| 多流派拟合 | 多为单流派或简单并列 | 七流派算法并行 + 聚合白话报告 | 既有引擎层 + `/api/report` 拟合叙事 |
| 报告可读性 | 术语堆砌、AI 腔 | 命理博主口语化风格包 | Prompt 风格蒸馏 + 可读性验收 |
| 出生地/常住地 | 常只采生辰 | 出生地校正真太阳时 + 常住地影响「口味/宜忌落地」 | 表单扩展 + city-coords + 报告上下文 |
| 社交破冰闭环 | 停在「看完报告」 | 报告后接吃什么 + 饭桌/酒桌游戏 | 结果页 CTA → 破冰模块 |
| 周边吃什么 | 纯文本菜名或无 | 城市/定位 → 店铺与菜品推荐（有降级） | 定位权限 + POI/清单 API + AI 背锅文案 |

说明：竞品具体功能细节未做实时抓取，上表为基于公开品类惯例的推断，标注为「此处未验证」。

### 1.2 三类用户画像

**画像 A：饭局破冰官**
- 角色：聚餐组织者/活跃分子
- 核心目标：10 分钟内让桌上一半人开口说话
- 对现有工具最大的不满：算命 App 太严肃，结果没法当话题；点菜又容易背锅
- 让他们愿意切换的那一个功能：报告后一键「今天吃什么 + 按人数推荐破冰游戏」

**画像 B：命理轻度爱好者**
- 角色：刷过八字/紫微短视频，想「验一下自己」
- 核心目标：看懂自己的命盘要点，而不是看天书
- 对现有工具最大的不满：AI 算得「看起来很准但看不懂」或「黑话正确、生活无关」
- 让他们愿意切换的那一个功能：七流派拟合后的白话概况 + 今日/本月/今年落地建议

**画像 C：好奇尝鲜用户**
- 角色：扫码进场、随手玩玩
- 核心目标：好玩、能分享、不羞耻
- 对现有工具最大的不满：要填一堆表、结果沉重或恐吓式话术
- 让他们愿意切换的那一个功能：对话式采集 + AI 背锅式轻松语气 + 可复制开场白

### 1.3 可行性边界

| 在范围内（及原因） | 明确排除在外（及原因） |
|---|---|
| 七流派排盘与综合测算（既有半成品） | 真实命理师真人咨询排班（非本产品形态） |
| AI 对话采集、白话报告、追问 | 医疗/法律/投资决策建议（合规风险） |
| 出生地/常住地字段与报告上下文 | 承诺「绝对准确」或恐吓式宿命论 |
| 「今天吃什么」推荐与 AI 背锅话术 | 无授权爬取外卖平台订单/评价原文 |
| 浏览器定位 + 周边 POI（有 Key 时）或城市清单降级 | 假装实时周边却用假店铺数据冒充真实 |
| 饭桌/酒桌小游戏推荐（按人数） | 赌博、色情、人身攻击类游戏 |
| 分享文案/卡片（P1） | 完整用户账号体系、跨设备云同步（P0 不做） |
| 移动优先 Web | 原生 iOS/Android App、强制登录 |

### 1.4 约束分层

| 硬约束 | 推荐默认 | 发挥空间 |
|---|---|---|
| 算法引擎与 AI 解读严格分层；排盘结果不得被 AI「改写为假数据」 | 沿用 Next.js 16 + 既有七引擎 + `/api/chat` `/api/report` | 视觉动效、插画、微文案、空状态 |
| 所有对外结果页必须有娱乐免责声明 | 报告四 Tab：概况/今日/本月/今年（与 MIGRATION 一致） | Tab 内排版节奏、引用金句样式 |
| 报告正文须通过「白话可读」验收（见第十章） | 风格包默认「中式命理博主口语」，可切换轻度/正式 | 风格包音色细节、博主口吻蒸馏质量 |
| 不输出未成年饮酒诱导；酒桌游戏需年龄提示 | 破冰游戏库本地 JSON，按人数/场景过滤 | 游戏卡片交互、随机洗牌动画 |
| 周边店铺：无真实 POI 时必须明确「清单推荐/示例」标签 | P0 用常住城市 + 品类清单；P1 接地图 POI | 店铺卡 UI、距离展示 |
| 不收集非必要隐私；生辰本地会话优先 | 无账号；会话态存 sessionStorage | 本地历史列表体验 |

## 第二章：整体布局与导航

### 2.1 信息架构

```text
天机阁
+-- 首页 /
|   +-- Hero：品牌 + 一句话价值 + CTA「一键综合测算」
|   +-- 七流派入口卡片
|   +-- 次 CTA：「今天吃什么（AI 背锅）」
+-- 综合测算 /unified          ← P0 主路径
|   +-- 对话采集
|   +-- 多流派结果并列
|   +-- 白话四 Tab 报告
|   +-- 破冰续航区（吃什么 / 小游戏）
+-- 单流派 /bazi|/ziwei|...    ← 保留既有
+-- 破冰独立页 /icebreak       ← P0 可由报告内嵌，P1 可直达
+-- 今日吃什么 /eat            ← P1 可从首页直达
```

### 2.2 主路径布局（移动端优先）

```text
+--------------------------------------+
|  Navbar（品牌「天机阁」+ 汉堡菜单） ~56px |
+--------------------------------------+
|  进度条：采集 → 排盘 → 报告 → 破冰   ~8px |
+--------------------------------------+
|                                      |
|  主内容区（约 78%）                    |
|  +--------------------------------+  |
|  | 对话气泡 / 命盘卡 / 报告 Tab     |  |
|  | 示例：概况 · 今日 · 本月 · 今年  |  |
|  +--------------------------------+  |
|                                      |
+--------------------------------------+
|  底栏 CTA（约 14%）                   |
|  「继续追问」 「今天吃什么」 「破冰游戏」   |
+--------------------------------------+
|  免责声明一行小字                     |
+--------------------------------------+
```

### 2.3 用户主流程

```text
打开首页
    |
    v
点「一键综合测算」
    |
    v
AI 对话采集：生辰/性别/出生地/常住地（可选定位）
    |
    +-- 信息不完整 --> 继续追问字段
    |
    +-- 信息完整 --> 七引擎并行排盘
                        |
                        v
                   展示摘要 + 白话报告
                        |
                        +-- 用户点「今天吃什么」--> 口味+城市推荐（AI 背锅）
                        |
                        +-- 用户点「破冰游戏」--> 输入人数/场景 --> 游戏清单
                        |
                        +-- 用户追问 --> FollowUpChat
```

布局理由：用户主要在手机上用；主路径是「算完就能说话」，因此报告页底部固定破冰 CTA，避免结果沉在术语里无法回流社交场景。

#### b) 交互流程

#### c) 状态清单

| 名称 | 触发条件 | 视觉标识 | 退出条件 |
|---|---|---|---|
| idle | 进入页 | 欢迎气泡 | 用户发送首条 |
| collecting | 缺字段 | 进度「采集中」 | 字段齐备 |
| validating | 本地校验中 | 主操作呈 loading | 通过/失败 |

| error | 校验/流式失败 | 红色提示 + 重试 | 用户重试或改表单 |

#### d) 依赖关系

- 读：用户消息、可选 geolocation
- 写：`BirthProfile`（会话）、触发引擎输入

#### e) 待决问题

1. 常住地是否必填：推荐默认「选填，但报告会提示完善后更贴口味」。
2. 时辰未知时是否允许「未知时辰」排盘：推荐默认允许，报告标注置信度降低。

## 第四章：超越竞品的差异化功能

### 第 4.1 节 七流派冲突可视化的白话拟合

1. 竞品为何没有这个功能：基于公开信息的推断——多数产品绑定单一流派 IP 或内容库，并列多引擎会暴露「说法打架」，对内容一致性运营不友好。
2. 本产品如何实现：引擎层如实输出；报告层增加「一致点 / 分歧点」结构化字段，AI 只解释冲突不抹平数据。推荐默认在概况 Tab 顶部展示 3 条一致、最多 2 条分歧。
3. 交互流程：

```text
七 Result → conflict_extractor（规则+轻量 LLM）→ 概况首屏
用户点分歧 → 展开各流派原句摘要（非改数据）
```

4. 风险与应对：冲突提取不准 → 宁可少展示；失败则隐藏该区块，不影响主报告。

### 第 4.2 节 AI 背锅式「今天吃什么」

1. 竞品为何没有：算命产品商业目标通常是测算次数/付费解读，不是解决点菜冲突；美食产品又缺少命理语境。
2. 本产品如何实现：用报告中的宜忌/五行/口味线索做软约束，召回菜品与店铺后，用幽默「背锅」文案包装；硬约束是来源标签诚实。
3. 交互流程：

```text
报告完成 → CTA「今天吃什么」→ 城市/定位召回 → 背锅文案 → 分享
```

4. 风险与应对：用户当真迷信忌口导致健康问题 → 文案声明「娱乐推荐，过敏与医嘱优先」；无 POI 时绝不伪造店名坐标。

### 第 4.3 节 报告后破冰游戏续航

1. 竞品为何没有：内容停在「看完即走」，缺少线下场景续航；游戏库运营不属于命理团队 KPI（推断）。
2. 本产品如何实现：本地游戏目录按人数/场景过滤，并用报告关键词生成 30 秒主持词。
3. 交互流程：

```text
报告 → 破冰 → 人数/场景 → 3 游戏 + 主持词 → 复制到微信
```

4. 风险与应对：酒桌游戏尺度 → 年龄确认 + 禁止危险饮酒惩罚；版权游戏玩法用自研规则描述，不抄袭商标化玩法名称（若存疑则改名）。
